

### 平台名称建议

**Claude Agent Platform** —— 一个基于 FastAPI + Claude Agent SDK 的通用 Skill 部署平台，底层模型通过 Google Vertex AI 调用 Claude 系列模型。

### 一、平台核心目标

构建一个通用的 AI Agent 平台，支持部署多种包含 **Skill** 的应用。平台严格遵循 Claude Agent SDK 使用规则：

- 优先使用 SDK 原生基础能力（文件读、写、编辑、搜索等）
- 仅在需要与外部系统交互时使用 MCP Servers
- SDK 自动生成 `session_id`，多轮对话通过 `resume` 机制实现
- Chat 接口与文件上传接口完全分离

### 二、整体架构设计

**关键概念**：

- **Skill**：可复用的领域能力包（例如 FastAPI 开发 Skill、代码重构 Skill、文档分析 Skill 等）
- **App（应用）**：平台上部署的一个实例 = 一个 Skill + 独立工作目录（cwd） + 权限配置
- **Session**：业务层 `business_session_id` 与 SDK 生成的 `sdk_session_id` 进行映射管理

**目录结构（推荐）**：

```
platform/
├── conf/                          # 配置文件目录
│   ├── config.yaml                # 主配置
│   ├── config.dev.yaml
│   └── config.prod.yaml
├── .claude/
│   └── skills/                    # ← Skill 标准路径（官方推荐）
│       └── fastapi-dev/           # 示例 Skill
│           └── SKILL.md
├── uploads/
│   └── temp/                      # 文件上传临时目录
├── app/
│   ├── core/
│   │   ├── config.py              # 配置加载模块
│   │   ├── session_manager.py     # 会话映射管理
│   │   └── permissions.py         # 权限控制 hook
│   ├── api/
│   │   ├── chat.py                # 对话接口（streaming）
│   │   └── upload.py              # 文件上传接口（独立）
│   ├── agents/
│   │   └── client.py              # # ClaudeSDKClient 封装（支持 Vertex AI）
│   └── mcp/                       # MCP Servers（仅外部交互使用）
├── AGENTS.md                      # 平台级规则文件
└── main.py
```

### 三、配置文件设计（conf/config.yaml）

平台所有配置统一从 `conf/` 目录下的 YAML 文件读取，支持多环境切换。

**主要配置模块**：

- `app`：平台基本信息（name、version、environment、host、port）
- `claude`：Claude Agent SDK 相关配置
  - `model`：推荐 `claude-3-5-sonnet-20241022` 或更新版本
  - `permission_mode`：默认权限模式（default / read_only / manual）
  - `default_allowed_tools`：优先使用 SDK 原生工具列表（read, write, edit, glob, grep, list_files 等）
  - `mcp_enabled`：是否启用 MCP（默认 false）
  - `mcp_servers`：仅在需要外部交互时配置
- `session`：会话映射配置（redis_url、mapping_ttl）
- `upload`：文件上传配置（temp_dir、max_file_size_mb、allowed_extensions）
- `security`：安全与权限设置（can_use_tool_hook、require_approval_for_write）
- `logging`：日志配置

配置加载逻辑：

- 默认读取 `conf/config.yaml`
- 支持通过环境变量 `ENV=dev` / `ENV=prod` 切换到对应配置文件
- 使用 Pydantic V2进行类型验证和解析

### 四、接口设计（Chat 与 Upload 分离）

1. **文件上传接口**：`POST /upload`

   - 接收文件并保存到临时目录
   - 返回文件元数据（`file_id`、`saved_path`、`original_name`、`size` 等）
   - **不**直接调用 Agent，仅负责存储
   - 支持大小限制和扩展名白名单
2. **对话接口**：`POST /chat`

   - 参数：`message`、`business_session_id`、`app_id`/`skill_name`、`file_ids`（可选，已上传文件列表）
   - 支持 streaming 返回（thinking、tool_call、observation、final answer）
   - 内部流程：
     - 通过 SessionManager 获取或捕获 SDK `session_id`
     - 加载对应 Skill 的指令
     - 调用 Claude Agent SDK（使用 `resume` 实现多轮）
     - 严格限制 `allowed_tools` 为 SDK 原生工具
     - MCP 仅在 Skill 需要外部交互时动态启用
   - 每次 tool call 后记录日志

### 五、会话管理机制

- 平台自行生成和管理 `business_session_id`（用户可见）
- SDK `session_id` 由 Claude Agent SDK 自动产生
- **首次对话**：不传 `resume`，让 SDK 生成 `session_id`，并从返回结果中捕获后建立映射
- **后续对话**：使用 `resume=sdk_session_id` 继续会话
- 映射关系建议使用 Redis 存储（带 TTL）
- 支持 session fork 用于实验性分支

### 六、Tool 使用原则（严格遵守 SDK 规则）

- **优先级**：
  1. Claude Agent SDK 原生工具（文件增删改查、代码编辑等）
  2. 仅当需要与外部系统交互时，才使用 MCP Servers
- 规划阶段默认使用 `read_only` 权限
- 执行阶段通过 `can_use_tool` hook + `permission_mode` 控制写入操作
- 所有文件操作必须通过 SDK 内置工具完成

### 七、平台级 AGENTS.md 核心规则

`AGENTS.md` 是平台行为准则，必须包含以下关键内容：

- 平台整体目标与非协商规则
- 配置管理要求（所有配置来自 conf/ 下的 YAML）
- 会话管理规则（必须捕获 SDK 生成的 session_id，使用 resume 继续）
- Tool 使用优先级（SDK 原生 > MCP）
- 接口分离原则（上传与 Chat 分开）
- Skill 部署与使用规范
- 安全与权限要求（永远不暴露密钥，规划与执行分离）
- 日志记录要求（每次 tool call 必须记录）

### 八、Skill 机制

- 每个 Skill 存放在  `.claude/skills/` 风格的结构中
- 包含 `SKILL.md` 文件定义领域指令、工作流和推荐工具
- 部署应用时，选择 Skill 并创建独立工作目录
- Skill 可预定义默认 prompt 模板和 allowed_tools

### 总结优势

- 配置集中管理，易于多环境部署
- 接口清晰分离，安全性更高
- 严格遵循 Claude Agent SDK 最佳实践
- 支持 Skill 复用，实现真正通用的 Agent 平台
- 会话机制可靠，支持长多轮对话
- 文件操作安全，受控，且优先使用 SDK 原生能力

这个方案已将之前讨论的所有要点（配置文件 YAML、session 管理、接口分离、Tool 优先级、Skill 部署、AGENTS.md 规则等）全部整合为一个连贯的设计。
